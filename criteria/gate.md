# Gate criteria (GATE), package mittens_gate

| ID | Level | Requirement | Proved by |
| --- | --- | --- | --- |
| GATE-001 | MUST | The handle the isolate receives MUST expose read methods only, so a direct call to any write method MUST be rejected (split from the prototype's token rule, cited once in the sandbox file). | adversarial: a program calls `env.GH.createComment(...)` and catches the rejection; expected error null, result `{ "write": "rejected" }`. The case proves the behaviour, not the runtime's error text, which differs between production and the test runtime |
| GATE-002 | MUST | A program MUST only return writes as a plan, and the plan MUST execute only after a human approves the `apply_writes` call; a rejected call MUST execute nothing and the model MUST receive `execution-denied` (was KCM-003). | exact: the stale pull request flow on repo-small; approve gives applied 5, failed 0; reject gives zero writes received by the stub |
| GATE-003 | MUST | Plan validation MUST refuse the whole plan when it holds a kind other than comment, close pull request or close issue, more than 25 writes, or a comment body over 4,000 characters. The refusal of another kind MUST read `Plan refused: write kind '<kind>' is not allowed`. A plan with no writes MUST be refused with `Plan refused: a plan needs at least 1 write`. A refused plan MUST NOT reach the human: no approval is asked for it. | exact: a 26-write plan and a 4,001-character comment each return the exact refusal and the stub receives zero writes; a plan with the kind `delete_branch` returns the exact refusal; an empty plan returns the exact refusal; in each of these no approval is asked |
| GATE-004 | SHOULD | Every read SHOULD validate its input on the host before it touches the driver, because the input comes from generated code (was KCM-009). The error SHOULD read `<method>: '<field>' <reason>`, with the name of the read that was called. | exact: a program passes a string where a number is required; expected the exact validation error and driver call count 0 |
| GATE-005 | MUST | `defineReads` MUST accept a map from method name to `{ input, output, handler }`, MUST throw a `TypeError` when an entry lacks any of the three, and MUST return `{ facade, spec }` where `spec()` is the declaration text the model reads. | contract: `facade.spec` equals the exact declaration string; a map with a missing `input` throws the exact message |
| GATE-006 | MUST | `defineWrites` MUST accept a map from write kind to `{ input, apply }` plus `limits`, and MUST return `{ planSpec, validatePlan, applyWritesTool }`, where the tool carries `needsApproval: true` and is never placed inside the sandbox. | contract: `plan.spec` equals the exact declaration string; the tool's `needsApproval` is true; the returned keys match exactly |
